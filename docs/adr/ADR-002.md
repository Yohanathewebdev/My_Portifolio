# ADR-002: Public site origins

- **Status:** Accepted
- **Date:** SDD v3.0

## Context

The public portfolio and the authenticated CMS have different trust
boundaries. Section 16 requires portfolio-specific public URLs, while §24
identifies stored XSS and credential exposure as security concerns. The URL
choice also needs to leave room for custom domains without making every
portfolio path a special case.

## Decision

Serve each published portfolio from a subdomain on the public site origin,
separate from the CMS origin. Host resolution maps the requested hostname to a
portfolio and public selectors only return published content. Custom domains
are an extension of the same host-resolution mechanism. Wildcard DNS and
wildcard TLS cover the platform-managed subdomains.

## Alternatives considered

- **`/p/<slug>/` on the CMS origin:** rejected because public content and CMS
  credentials share an origin; a stored-XSS defect would have a larger blast
  radius.
- **A separate deployment per portfolio:** rejected because operations,
  upgrades, and resource usage would scale with tenant count.
- **Client-side hostname routing only:** rejected because server-side
  resolution is needed for SEO, cache keys, and consistent publication checks.

## Consequences

DNS and certificate automation become platform responsibilities. Cache keys,
canonical URLs, preview links, and CORS policies must distinguish public and
CMS origins. The separation limits the impact of public rendering defects and
makes custom domains a routing concern rather than a content migration.
