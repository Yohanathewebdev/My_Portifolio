# ADR-007: PDF rendering

- **Status:** Accepted
- **Date:** SDD v3.0

## Context

CV export needs predictable pagination, accessible document structure, and
repeatable output in a worker. The renderer must run without a browser fleet,
must be sandboxable, and must fit the asynchronous `pdf` queue described in
§29.2. Theme authors need familiar HTML/CSS rather than a separate document
language.

## Decision

Use WeasyPrint to render Django-template output and immutable CV snapshots into
PDF. Workers run the renderer with explicit resource and timeout controls,
store checksums and page metadata, and report failures through the task
workflow. Supported CSS is documented for theme authors and validated by
render fixtures.

## Alternatives considered

- **Headless Chromium:** rejected because the browser process is heavier to
  operate and sandbox, with more variability across versions.
- **LaTeX:** rejected because it introduces a separate authoring language and
  makes theme customization less accessible.
- **Client-side PDF generation:** rejected because output quality, fonts, and
  reproducibility would depend on the user's browser.

## Consequences

We accept that some advanced CSS is unsupported and must maintain a supported
theme subset. In return, rendering is deterministic, relatively lightweight,
easy to isolate in workers, and aligned with the server-rendered public
template architecture.
